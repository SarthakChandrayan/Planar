Meeting → plan · runs on a laptop

Turn a meeting into a plan you can check.

Paste a meeting transcript. Planar pulls out the decisions, requirements, tasks, risks and open questions, links each one to the lines that said it, and drafts an implementation plan. A local model does the reading, so the transcript never leaves the machine.

02

How it works

A small model does one narrow job at a time, and the backend checks everything it says against the transcript before keeping it.

  1. read

    Number the lines

    Speakers and timestamps are detected and every non-blank line gets a number. Long meetings are split into overlapping chunks instead of being cut off.

  2. extract

    Focused passes

    Decisions, then requirements, tasks, and risks with open questions. Each pass is a separate call, constrained to a JSON schema, citing line numbers rather than quoting. A second look asks only for what the first one missed.

  3. check

    Ground every item

    The cited lines must support the claim. "Should" stays "should", numbers and dates must exist in the meeting, an answered question is not open, and a rule restated as a risk is dropped.

  4. link

    Trace and plan

    Links between items come from shared evidence, not the model. Plan steps cite the decisions, requirements and tasks they apply, and the plan map draws why → what → how → who.

03

Measured accuracy

Each sample meeting has a hand-written answer key: what was really decided, required, assigned, worried about and left open, with the lines that say so. Output is matched by line, not wording, so the score doesn't reward a phrasing.

What the scores say. The model misses things more often than it invents them. In these recorded runs about 9 in 10 extracted items are right, but only about 6 in 10 real items are found. A "second look" pass, added after these runs and re-measured on five meetings, lifts recall to about 7 in 10 with no more invented items.

How it got here. Every change is judged by these scores across all meetings, never by one good-looking report. Ideas that sounded better but scored worse, such as extracting one topic at a time, were measured and removed.

04

Run it yourself

Windows, macOS or Linux with Python 3.12, Node 22 and Ollama. 16 GB of RAM is enough for the 8B model.

Set up

# the model, about 5 GB
ollama pull qwen3:8b

git clone https://github.com/SarthakChandrayan/SpecForge planar
cd planar

# backend
cd backend
python -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
cd ..

# frontend
cd frontend
npm install
cd ..

# use the 8B model
echo OLLAMA_MODEL=qwen3:8b > .env

Start

# terminal 1
ollama serve

# terminal 2: backend + frontend
.\start.ps1

Open localhost:5173, paste a transcript or pick a sample, and press Analyze. On a laptop with Intel graphics, enabling Ollama's Vulkan backend (OLLAMA_IGPU_ENABLE=1) roughly halves the run time.

Score a run against the answer keys: backend\.venv\Scripts\python backend\scripts\score.py
